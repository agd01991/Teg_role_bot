## Фактические проверки этой задачи

Зависимости установлены в отдельное локальное окружение из `experiments/telegram_probe/requirements.lock`. PR #10 проверен в экспорте **точного** `13603e5`, отдельно от документальных правок; исходники доступны через `PYTHONPATH`. Команды выполнены из корня рабочей копии:

```powershell
.\.venv-review\Scripts\python.exe -m pip install -r experiments/telegram_probe/requirements.lock black ruff
# Затем локальное окружение переименовано в .venv.
git --git-dir=.git --work-tree=. archive -o .venv/pr10.tar origin/m4plkv-codex/-res-001
.\.venv\Scripts\python.exe -m tarfile -e .venv/pr10.tar .venv/pr10
$env:PYTHONPATH = [IO.Path]::GetFullPath('.venv/pr10/experiments/telegram_probe/src')
.\.venv\Scripts\python.exe -m unittest discover -s .venv/pr10/experiments/telegram_probe/tests -v
.\.venv\Scripts\python.exe -m black --check --exclude '^$' .venv/pr10/experiments/telegram_probe/src .venv/pr10/experiments/telegram_probe/tests
.\.venv\Scripts\python.exe -m ruff check --isolated --select E4,E7,E9,F --output-format concise .venv/pr10/experiments/telegram_probe/src .venv/pr10/experiments/telegram_probe/tests
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe .venv/check_docs.py
git --git-dir=.git --work-tree=. diff --check
```

Результат: чистая установка завершена; 47 тестов — OK; Black 26.10.1 проверил все 6 Python-файлов; базовые правила Ruff 0.17.1 и `pip check` пройдены; локальный одноразовый `check_docs.py` проверил 10 Markdown-файлов, локальные ссылки/якоря, 25 таблиц, уникальность/непрерывность A/D и P0 gate; `diff --check` без ошибок. Обычный `ruff check` и `ruff check --isolated` в 0.17.1 включают более широкий набор правил и выявили **18** замечаний на исходном head PR #10; они не объявляются пройденными и исправляются отдельно от DOC-003. Первоначальный Black с путями внутри `.venv` пропустил файлы: зачтён только повтор с `--exclude '^$'`. Первая сетевая установка из песочницы не удалась; повтор с разрешённым сетевым доступом завершился успешно.

Настоящий Telegram, зарегистрированный username в R1-U, Android/iOS/Desktop, PostgreSQL и продуктовая матрица не проверялись: отсутствуют требуемые тестовые доступы/среды. Автотесты и документальная проверка не меняют их статусы на «пройдено».

## Открытые решения и следующий инженерный этап

- Первичное назначение администратора продукта, передача управления и восстановление доступа блокируют окончательный onboarding/AUTH-001.
- Судьба старых `#`, `~`, `/ping`, `/tag` должна быть решена до продуктового парсера. RES-001 должен реально проверить целевой `@бот @код`, конфликт с Telegram username и платформенные ограничения.
- Для P1 открыты точный UX подтверждения после вытеснения личного имени, точки входа Mini App, непосредственная отправка и пакетная семантика. Эти вопросы не переносят Mini App или личные команды в P0.
- PostgreSQL остаётся целью пилота; DATA_MODEL — логическая модель, не утверждённые DDL/миграции.

RES-001 остаётся незавершённым до реальных испытаний по [протоколу](research/RES-001.md). Следующий инженерный этап после исследования — OPS-001; DOC-003 не меняет эту последовательность и не засчитывает probe как продуктовую приёмку.
