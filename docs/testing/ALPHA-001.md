# ALPHA-001: промежуточный этап для Telegram-тестирования

Дата: 21 октября 2026 года. Среда: Windows, CPython 3.12.14, aiogram 3.31.0, asyncpg 0.31.0, PostgreSQL 17.11 в Docker Desktop. Ветка `feat/telegram-test-alpha` начинается от `35c6cdf` (`fix/pr-10-probe-checks`), включает требования DOC-003 из PR #12 и их уточнения. PR #9/#10/#12/#13 остаются отдельными незавершёнными предложениями; автоматического слияния нет.

## Выполненные проверки

Из корня репозитория выполнены:

```powershell
.\start-test.ps1 -SetupOnly
.\.venv-alpha\Scripts\python.exe alpha/check.py
.\.venv\Scripts\python.exe -m black --check alpha
.\.venv\Scripts\python.exe -m ruff check alpha
```

Результат полного прогона: **51 тест OK**, без пропусков, 48,987 секунды. Это 8 проверок парсера/конфигурации/логов, 34 интеграционных сценария с настоящим PostgreSQL и 9 сценариев через настоящий aiogram Dispatcher с управляемым транспортом Telegram. Black и Ruff прошли.

Проверены tenant FK, актуальность прав/членства, выход и повторный вход автора/получателя, явное подтверждение, лимиты и конкурентные вызовы, постоянная дедупликация update/сообщения, темы/reply/HTML, opt-out во время ожидания, ограниченный retry_after, сетевой исход uncertain, stop во время отправки, отмена очереди при перезапуске, глобальное удаление и воспроизведение независимого журнала после возврата старой БД. Проверка восстановления использует сохранённое предыдущее состояние БД в интеграционном сценарии; полноценный операционный backup/restore drill с архивом PostgreSQL пока не выполнен.

Рабочий PostgreSQL поднят на localhost; приложение использует отдельную роль без superuser/создания БД/ролей. Начальная схема создаётся идемпотентно; переход между будущими версиями схемы и rollback ещё не реализованы. Тесты запускаются только на БД с суффиксом `_tests`.

## Ручной прогон в Telegram

Следуйте [инструкции запуска](../../alpha/README.md). Для каждого случая запишите только результат, версию клиента и безопасное описание, без токена, переписки и выгрузки чужих ID.

| Сценарий | Ожидаемый результат | Фактический результат |
| --- | --- | --- |
| Создать → подтвердить → reply-назначить → вызвать от обычного участника | Одна роль; упоминание получателя, не автора; продуктовые права для вызова не нужны | Ожидает тестового бота |
| Вызов в теме форума и reply на сообщение | Ответ на сообщение вызова в той же теме; при недоступной теме нет отправки в другую | Ожидает тестового бота |
| Два начальных кода / пояснение через `--` | Два кода отклонены целиком; пояснение не расширяет состав | Ожидает тестового бота |
| Получатель без username и без `/start` | Ссылка по ID; проверить кликабельность и уведомление отдельно | Ожидает тестового бота/клиентов |
| `/optout`, повторное назначение, новый вызов | Нет упоминания отказавшегося участника | Ожидает тестового бота |
| Выход/возврат участника и продуктового администратора | Старые назначения/права не возвращаются; старые вызовы не оживают | Ожидает тестового бота |
| Перезапуск при очереди; `/jobs`, `/stop` | Старый остаток отменён; подтверждённые части не повторены | Ожидает тестового бота |
| `/delete_me confirm` в ЛС после выхода из группы | Профиль удалён во всех чатах; новый вход не восстанавливает назначения | Ожидает тестового бота |
| Android / iOS / Desktop, Privacy Mode, конфликт кода с username | Зафиксировать реальные entities, отображение и ограничения R1–R5/R1-U | Ожидает устройств и RES-001 |

Управляемый транспорт не доказывает push-уведомления, поведение настоящих клиентов, окончательные права BotFather/Privacy Mode или API в реальной сети. Поэтому статусы A01–A63 в [общей приёмке](../ACCEPTANCE.md) не заменены на «пройдено».

## Границы этапа

Альфа предназначена для закрытой согласованной группы; это не публичный P0-релиз и не замена RES-001, DATA-001, AUTH-001 или P0-OPS-001. Полный жизненный цикл ролей, self-service, настройки политик/quiet hours, onboarding, удаление отдельного чата, экспорт, нагрузка, независимые эксплуатационные резервные копии и миграции остаются дальнейшими задачами. Общая и личная модель P1, включая маркеры вытеснения, описана в требованиях, но недоступна в этой реализации.

Одна промежуточная попытка прервана из-за остановленного Docker Desktop и не засчитана. После восстановления временных сокетов без изменения volume полный прогон повторён: 51/51. Удалённый профиль также не воссоздаётся входящими событиями членства до собственного optin.
