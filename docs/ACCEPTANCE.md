# Критерии приёмки A01–A63

A01–A55 происходят из раздела 11 [ТЗ версии 3](SPEC.md) и сохраняют идентификаторы; затронутые формулировки актуализированы DOC-003. A56–A63 добавлены для новой модели. Бизнес-правила, подмена контекста, повторы, порядок событий и сбои должны проверяться автоматически на целевой БД и управляемых ответах Telegram API; пользовательские сценарии и реальные ограничения — дополнительно с Telegram-аккаунтами в отдельных группах на Android, iOS и Desktop. Успешный HTTP-ответ сам по себе не подтверждает доставку уведомления.

## Применимость и правила результата

- Перед **P0** обязательны A01–A29, A34, A35, A37, A39–A51, A53–A56, A61 и A63 **в применимой части**. A56 проверяет изоляцию полномочий, A61 — общие команды и единую личность без `/start`, A63 — ID/версии общих объектов. Для отложенной функции проверяется её недоступность, а не преждевременная реализация. Для A39 до решения о совместимости обязателен безопасный отказ; после одобрения — функциональная проверка одобренных форм.
- Перед **P1** обязателен весь набор, включая платежи, личные команды и Mini App.
- **A52** обязателен только перед выпуском опциональной функции `all`; это не делает `all` обязательной частью базового P1.
- Критические дефекты: межчатовая утечка, повышение прав, повторный платёж, потеря ролей и массовый повтор упоминаний.
- Во всех строках исходный статус — **не выполнялась**. Подтверждение заполняется только после фактической проверки ссылкой на лог, тест, протокол или иной артефакт.

## Общие условия сдачи из ТЗ

Результат разработки включает репозиторий, инструкции запуска, миграции, описание конфигурации без секретов, тесты основных правил и интеграций, шаблоны политик и тарифов, руководство администратора, журнал известных ограничений, процедуру восстановления и протокол приёмки. Одного работающего примера команды для сдачи продукта недостаточно.

Проект должен запускаться из чистого окружения по README. Перед выпуском выполняются проверки стиля и типов, миграций, соединений и корректного завершения процессов. Асинхронный ввод вывод не блокируется синхронными запросами. Проверки авторизации охватывают сервисный слой, а не только видимость кнопок.
