# Закрытая тестовая альфа

Эта версия позволяет проверить общие роли в отдельной Telegram-группе: создание с подтверждением, назначение через reply, вызов, отказ от упоминаний и удаление своего профиля. Это промежуточный этап ALPHA-001; полная приёмка P0 и исследование RES-001 ещё не завершены. Личные/скрытые роли, Mini App, платежи, переименование/архив ролей, заявки и массовый `all` пока недоступны.

## Первый запуск в Windows

Нужны Python 3.12, Docker Desktop с Linux containers и отдельный тестовый бот, зарегистрированный через BotFather. Используйте группу с согласившимися участниками. Добавьте туда бота администратором: это необходимо для надёжной проверки членства. Права удалять сообщения, блокировать людей, назначать администраторов и менять настройки ему не нужны. В группе должны быть разрешены текстовые сообщения бота.

Откройте PowerShell в рабочей папке:

```powershell
cd D:\tgBotRole2026
.\start-test.ps1 -Discover
```

Введите токен BotFather в скрытый запрос консоли. Он остаётся только в памяти процесса; не отправляйте его в переписку и не записывайте в команды. Напишите боту `/start` в личном диалоге, а в группе — `/id@ФактическоеИмяБота`. Консоль покажет только числовые `chat_id` и `user_id`. Остановите обнаружение через Ctrl+C.

Запустите приложение:

```powershell
.\start-test.ps1
```

При первом запуске укажите чат и своего продуктового администратора, например `-1001234567890:12345678`. Для нескольких администраторов: `-1001234567890:12345678,87654321`; несколько чатов разделяются `;`. Значения сохраняются в локальном `.alpha/chat-admins`. Затем снова введите токен в скрытый запрос. Появление строки «Тестовая альфа @… запущена» подтверждает готовность polling. Окно PowerShell оставьте открытым.

Скрипт создаёт изолированное окружение, устанавливает фиксированные зависимости и поднимает PostgreSQL. Если Docker ещё запускается, дождитесь его готовности и повторите команду. При блокировке скриптов политикой Windows используйте разрешённый в вашей системе способ запуска; менять постоянную политику безопасности не требуется.

## Проверка в группе

1. От своего продуктового администратора отправьте `/create разработка Разработка`.
2. Скопируйте предложенную команду `/confirm <одноразовый-токен>` и отправьте в том же чате в течение двух минут.
3. Ответьте на обычное сообщение другого согласившегося участника командой `/assign разработка`. Сам получатель может не открывать личный диалог с ботом.
4. От любого текущего участника отправьте `@ФактическоеИмяБота @разработка Проверка`. Бот упомянет назначенных участников ответом на исходное сообщение, в той же теме. Автор вызова исключается.
5. От получателя отправьте `/optout`. Следующий вызов не должен его упоминать, в том числе если вызов уже ожидал в очереди. `/optin` разрешает упоминания снова.

Между повторными вызовами учитывайте лимиты ниже. В группе с несколькими ботами адресуйте команды явно: `/roles@ФактическоеИмяБота`, `/assign@ФактическоеИмяБота разработка`.

| Команда | Действие |
| --- | --- |
| `/help`, `/id` | Справка и собственный ID; в группе также ID чата |
| `/roles` | Общие роли текущего чата и число назначений |
| `/create код Название`, `/confirm токен` | Создание роли продуктовым администратором |
| reply `/assign код`, `/unassign код` | Назначение/снятие участника продуктовым администратором |
| `@бот @код Пояснение` | Вызов одной общей роли |
| `/optout`, `/optin` | Личный отказ/возобновление упоминаний в этом чате |
| `/jobs` | Свои последние вызовы; продуктовый администратор видит вызовы чата |
| `/stop` | Отменить оставшиеся части своих вызовов; администратор может остановить очередь чата |
| `/delete_me`, затем `/delete_me confirm` | Удалить собственный профиль и назначения во всех чатах этой установки |

Начальный блок содержит ровно один код. `@бот @роль @другой` и `@бот @роль,@другой` отклоняются целиком. Первое обычное слово начинает пояснение: `@бот @роль Проверить @другой` вызывает только роль. Если пояснение начинается с упоминания, поставьте явную границу: `@бот @роль -- @другой проверь`. Старые `#роль`, `~роль`, `/tag` и `/ping` вызова не создают. Пересланные сообщения, цитаты, code/pre, подписи и редактирования не запускают рассылку.

## Полномочия и ограничения

Локальный владелец установки явно разрешает чаты и продуктовых администраторов. Нативное администрирование Telegram само по себе не даёт управления ролями. Обычный текущий участник может вызывать общие роли без продуктового разрешения на управление.

После выхода администратора из группы его продуктовые права отзываются; повторный вход не восстанавливает их или прежние назначения. При необходимости владелец установки может явно выдать права заново, остановив бота:

```powershell
.\start-test.ps1 -GrantChat -1001234567890 -GrantUser 12345678
.\start-test.ps1
```

Человек должен оставаться в локальном списке разрешённых администраторов и быть текущим участником чата. Это временный bootstrap закрытой альфы; окончательная передача владения и восстановление доступа по D-017 ещё требуют решения.

Лимиты: до 10 разрешённых чатов и 10 администраторов на чат; 20 ролей на чат, 20 назначений на роль, 5 получателей на сообщение. Вызовы ограничены одним в минуту и пятью в час для автора, одним в пять минут для роли и десятью в час для чата; одновременно до трёх ожидающих вызовов. Очередь живёт пять минут. Общий отправитель ограничивает также служебные ответы: не чаще сообщения в 3,5 секунды на чат и 20 сообщений в секунду глобально. `retry_after` сохраняется, попыток не более трёх. Это собственные консервативные ограничения альфы, а не обещание гарантированных лимитов Telegram.

PostgreSQL использует пул 1–4 соединения, индексы и транзакционную блокировку на чат. Снимок получателей не пополняется новыми назначениями. Перед отправкой заново проверяются членство, его версия, отказ получателя и роль. Одновременно с этой БД работает один процесс бота. История входящих событий/завершённых вызовов хранится семь дней, технический аудит — 30 дней; неопределённые отправки сохраняются до разбора. Имена ограничены по длине; текст переписки не сохраняется.

## Остановка, сбои и удаление

Ctrl+C останавливает бота; роли, назначения и отказы сохраняются в PostgreSQL. После нового запуска неотправленные части старых вызовов отменяются. Уже подтверждённые части сохраняют результат. Если Telegram мог принять отправку, но ответ потерялся, вызов получает состояние «нужна сверка результата», а новые вызовы этого чата блокируются. Автоматического повтора такой части нет.

Сначала проверьте сообщения в Telegram и номер вызова из `/jobs`. Затем остановите бота и закройте неопределённый вызов локальной командой:

```powershell
.\start-test.ps1 -ResolveJob 123
.\start-test.ps1
```

Она отменяет остаток, не повторяя отправку. `/stop` и удаление профиля также не могут отменить уже начатый запрос Telegram или удалить опубликованное сообщение.

Известный боту пользователь может выполнить `/delete_me confirm` в личном диалоге даже после выхода из всех тестовых групп. Удаляются профиль, назначения, настройки, авторские вызовы и ID из снимков получателей во всех чатах. Для запрета автоматического восстановления остаётся минимальная запись числового ID. Повторное участие требует собственного `/optin` и новых назначений; права администратора не возвращаются автоматически. Команда не удаляет сообщения из Telegram.

Каталог `.alpha` защищён Windows ACL и исключён из Git. В нём находятся пароли БД, настройки доступа и независимый журнал `deletions.jsonl`. БД слушает только `127.0.0.1:55432`, приложение подключается отдельной ролью без superuser/create-role/create-db. Не публикуйте и не отправляйте этот каталог.

Сохраняйте актуальный журнал удалений отдельно от снимка БД. После восстановления старой БД журнал воспроизводится до открытия бота/очереди. Отсутствующий, усечённый, повреждённый или чужой журнал блокирует запуск. Не заменяйте его старой копией вместе с БД и не удаляйте Docker volume. Полная эксплуатационная процедура резервирования/rollback и защита от утраты одновременно всех копий пока не приняты; не используйте эту альфу для публичного сервиса.

## Проверки и диагностика

```powershell
.\start-test.ps1 -SetupOnly
.\start-test.ps1 -Check
```

Первая команда готовит БД без токена и запуска polling. Вторая выполняет unit/integration тесты на отдельной БД `rolealpha_tests`; рабочая БД `rolealpha` не очищается. При отсутствии реального PostgreSQL полный прогон считается ошибкой, а не успехом с пропусками.

Проверенные команды, результаты и оставшиеся ручные сценарии: [ALPHA-001](../docs/testing/ALPHA-001.md). Сбой старта сообщает только безопасный тип ошибки. Не включайте подробное логирование HTTP: URL Telegram содержит токен. Если появилось сообщение о webhook, используйте отдельного тестового бота или осознанно снимите его прежнюю интеграцию; альфа сама webhook и накопленные updates не удаляет.

Docker Desktop должен показывать работающий Linux engine. При ошибке самого Docker сохраните его диагностическое сообщение; не выполняйте factory reset и удаление volume ради перезапуска бота. Образ PostgreSQL и действия CI закреплены digest/commit; обновлять их следует отдельной проверенной правкой.
